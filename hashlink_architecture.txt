BUILD OUTPUT FLOW
┌──────────────────────────────────────────────────────────────────────────────┐
│                                                                              │
│  haxe -hl output.c ... ──────────► HL-C Generation (Haxe compiler)         │
│                           │                                                 │
│                           ├──► output.c (Generated C code)                 │
│                           │         │                                      │
│                           │         ▼                                      │
│                           │   emcc output.c \                              │
│                           │       -o app.js \                              │
│                           │       -s WASM=1 \                              │
│                           │       -l hl ...  ──────► app.js + app.wasm    │
│                           │                                                │
│  haxe -hl hello.hl ... ──┴───────► HL Bytecode (Haxe compiler)            │
│                           │                                                │
│                           └──► hello.hl                                    │
│                                   │                                        │
│                                   ▼                                        │
│                           ./hl hello.hl ──────► JIT compile & execute     │
│                                   │                                        │
│                                   └──► x86/x64 code (on x86 only)          │
│                                                                            │
│  Two Paths:                                                               │
│  Path 1 (HL-C): Portable, works on WASM, ARM, etc.                       │
│  Path 2 (JIT): Fast on x86/x64, requires native platform                 │
│                                                                            │
└──────────────────────────────────────────────────────────────────────────────┘


WASM COMPILATION REQUIREMENTS
┌──────────────────────────────────────────────────────────────────────────────┐
│                                                                              │
│  REQUIRED (minimal runtime):                                                │
│  ├─ allocator.c (Emscripten hooks: emscripten_builtin_*)                  │
│  ├─ gc.c (Emscripten memory management)                                   │
│  ├─ src/std/obj.c, types.c, string.c, bytes.c, buffer.c                  │
│  ├─ src/std/cast.c, error.c, fun.c, maps.c, array.c                      │
│  ├─ src/std/ucs2.c (Unicode)                                              │
│  └─ src/std/sys.c (WASM stub version)                                     │
│                                                                            │
│  OPTIONAL (as needed):                                                     │
│  ├─ PCRE2 (regex) ◄─ regexp.c dependency                                  │
│  ├─ src/std/random.c (C stdlib RNG)                                       │
│  ├─ src/std/date.c (system time calls)                                    │
│  └─ src/std/file.c (WASM VFS or memfs)                                    │
│                                                                            │
│  SHOULD DISABLE for WASM:                                                 │
│  ├─ jit.c (x86/x64 only, Emscripten compiles anyway)                     │
│  ├─ src/std/thread.c (WASM single-threaded) ◄─ Set -DHL_NO_THREADS       │
│  ├─ src/std/socket.c (limited WASM socket API)                           │
│  ├─ src/std/process.c (WASM has no process model)                        │
│  ├─ debugger.c (unless need runtime debugging)                           │
│  └─ profile.c (optional profiling)                                        │
